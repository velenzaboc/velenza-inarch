## Reading the numbers

- Every sample is one OS process from spawn to exit, so it includes process start-up, config discovery and store open for `inr` and the equivalent start-up for `git`. The git `land` agent is a `bash -c` child running commit, push and the rebase retry loop.
- Peak RSS is the resident-set high-water mark of the largest process in the agent's process tree (KiB). Latency and RSS statistics cover successful samples only; the fail column and the Failures section carry the rest.
- `provision` destinations are deleted between trials; the git bare origin is packed once; page cache is warm after the warm-up trial for both systems.
- `land` agents_ok counts changes that were read back from the branch head after the batch. A value below K is a lost update and is reported, not hidden.
- `inr` land traffic crosses one loopback HTTP server (same machine), git pushes go to a bare repository on the same filesystem. Neither side pays real network latency.
- Nothing in this directory identifies the machine beyond the host label and the hardware fields above.
